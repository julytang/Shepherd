# 外层协议（草案）

状态：草案，尚未实现。设计参考 Orca 的 `cloud/packages/relay-contract`（MIT），去掉了账号层和多节点调度。只借鉴设计，不复制代码。

协议分两层。本文只定义外层，即服务端参与的部分。内层（审批、会话、Diff）在 Mac 与手机之间端到端加密，由 `Packages/ShepherdRemote` 定义，服务端只转发密文。

## 角色

- **主机**：一台运行 Shepherd 的 Mac。
- **设备**：一台已绑定的 iPhone、iPad 或 iPhone Duo。
- **中继**、**推送网关**：见 README。

## 1. 主机认证

主机用密钥证明身份，没有账号。

1. 主机发 hello：协议版本、主机 ID、主机公钥。
2. 中继用主机公钥加密一个随机数，连同质询 ID 和过期时间发回。
3. 主机解密后，对「质询内容」计算 MAC 并回传。质询内容包含中继地址、主机 ID、主机公钥与时间，防止重放到别处。
4. 中继确认后，这条连接成为主机的控制连接。

## 2. 设备凭证

设备不直接证明身份，使用主机替它登记的凭证。

- **邀请令牌**：绑定时由主机请求中继生成。一次性，有过期时间和最多尝试次数。出现在 Mac 屏幕的二维码里。
- **续连令牌**：绑定成功后，主机为设备登记续连令牌的哈希。带版本号，可轮换；轮换时旧令牌有一段宽限期。中继只保存哈希。
- **吊销**：主机可以随时吊销某台设备，对应界面上的「解绑」。

## 3. 连接对接

1. 设备带凭证连接中继。
2. 中继校验凭证后通知主机，并给出一张连接票据。
3. 主机用票据另开一条数据连接。
4. 两条连接对上后，中继开始双向转发。
5. 两端完成端到端握手。握手不属于外层协议。

中继不缓存业务消息。设备重新连接后，由主机同步完整状态。

## 4. 推送

1. 主机用第 1 节的方式向推送网关证明身份，换取短期会话。
2. 主机为已绑定的设备登记推送令牌。
3. 设备不在线时，主机请求网关向该设备推送一段密文。
4. 设备上的通知扩展解密后显示。

## 5. 限流与错误

- 按主机密钥和来源地址限制：连接数、流量、每小时推送次数、邀请令牌的尝试次数。
- 错误码沿用 WebSocket 关闭码的 4xxx 段，具体取值实现时确定。

## 待定

- 加密算法与密钥格式。Mac 与 iOS 用 CryptoKit，服务端用 Node 自带的 `crypto`，两边需要一组共用的测试样本。
- 质询与票据的具体字段、过期时间、宽限期长度。
- 实时活动（Live Activity）的推送令牌是否与通知共用一套登记流程。
