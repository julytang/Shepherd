# Shepherd Server

Companion（iPhone、iPad、iPhone Duo）与 Mac 之间的中继，以及推送网关。Mac 端单独使用时不依赖这里的任何服务。

目前只有骨架，没有可用的实现。

## 两个程序

| 程序 | 职责 | 谁来运行 |
| :--- | :--- | :--- |
| `relay` | 验证主机密钥、管理设备凭证、对接连接后转发密文 | 官方默认中继；用户也可以自建 |
| `push` | 持有 APNs 密钥，替已绑定的手机发送加密通知 | 只有官方运行 |

两者分开部署。中继面对大量长连接，推送网关持有密钥，分开后中继出问题也接触不到密钥。自建中继的用户，Mac 端仍然向官方推送网关请求推送。

## 服务端能看到什么

- 能看到：主机公钥、设备凭证的哈希、配对关系、连接时间与流量、推送令牌。
- 看不到：审批内容、命令、代码、对话。这些在 Mac 与手机之间端到端加密，包括推送通知的内容。

## 不做账号

主机的身份就是它的密钥。任何人都可以注册成主机，所以默认中继只能按主机密钥与来源地址限流。

## 部署要求

- 推送网关单独部署。
- APNs 密钥限定到 `top.inorbit.shepherd` 这一个 App。
- 密钥只从服务器的密钥管理或环境变量读取，不进仓库、镜像、日志与备份。
- 日志只记汇总计数，不记令牌、通知内容与完整的主机标识。

## 本地运行

需要 Node 24 或更高版本，没有第三方依赖。

```sh
cd Server
npm test
```

协议见 [PROTOCOL.md](./PROTOCOL.md)。
